# Linking a process into the driver

Chain position: add-process-to-driver (write `<PROC>.map`, register, run
`maple makeproc`) → **link-to-driver**.

## Step 1 — verify the generated files

In `driver/process/<PROC>/`, for every non-empty layer of `XX` in the
`.map`, these must exist:

- **Full-ME layers** (calls to the full matrix elements with their
  colour/symmetry factors): `sigB<PROC>.f` (LO), `sigR<PROC>.f`,
  `sigV<PROC>.f`, `sigRR<PROC>.f`, `sigRV<PROC>.f`, `sigVV<PROC>.f`.
- **Counterterm layers** (built from the maple-level subtraction terms):
  `sigSNLO<PROC>.f` (R subtraction), `sigTNLO<PROC>.f` (V),
  `sigS<PROC>.f` (RR), `sigT<PROC>.f` (RV), `sigU<PROC>.f` (VV).
- **Channel bookkeeping**: `selectchannel<PROC>.f` and `qcdnorm<PROC>.f`
  (plus `lumi<PROC>.f`, `array<PROC>.dat`, `<PROC>-*.config`).

A missing file for a declared layer means makeproc did not complete —
go back to add-process-to-driver (check its stdout) rather than creating
files by hand.

## Step 2 — implement the auto*.f stubs

`makedummy` (called by makeproc) emits one `auto<ME><TAIL>.f` per
counterterm matrix element and layer (`TAIL` in `SNLO, TNLO, S, T, U`),
containing one function per initial-state crossing, ALL generated as
placeholders:

```fortran
      function qgB1g0ZSNLO(i1,i2,i3,i4,i5)
      implicit double precision (a-h,o-y)

      qgB1g0ZSNLO = 0d0

      return
      end
```

These must be turned into real wrappers. Two cases, modelled on the
corresponding files of a neighbouring process (same file name WITHOUT
the `auto` prefix, e.g. `driver/process/Z/B1g0ZSNLO.f`):

1. **Base crossing** → call the subtraction term generated at src level
   by the maple pipeline (`src/process/<DIR>/auto<name>.f`, from
   makefortRR/RV — see autogen-subtraction), with the correct argument
   order.
2. **Other crossings** → alias the base crossing (bridge pattern):

   ```fortran
   gqB1g0ZSNLO = qgB1g0ZSNLO(i1,i2,i3,i4,i5)
   ```

   Argument permutations between crossings must follow the neighbouring
   process's conventions — copy the structure, don't guess.

Signatures differ by layer and must be preserved exactly as generated:
`SNLO`/`S`: `(i1,...,iN)`; `TNLO`/`T`/`U`:
`(ix,x1,x2,i1,...,iN,renscale2,facscale2)`.

**Then rename each completed file removing the `auto` prefix**
(`autoB1g0ZSNLO.f` → `B1g0ZSNLO.f`). The `auto*` name is the
regeneration target: the next makeproc run overwrites `auto*` stubs,
while the renamed file preserves the hand-written wrappers. Use `hg add`
for the new files; leave or remove the `auto*` originals as the user
prefers (they are regenerated anyway).

## Step 3 — completeness check

After renaming, verify no placeholder survived:

- grep the renamed counterterm files for `= 0d0` bodies — every function
  must either compute or delegate;
- every function name referenced in `sigSNLO/sigTNLO/sigS/sigT/sigU
  <PROC>.f` and in `selectchannel<PROC>.f` sub_str entries must be
  defined in exactly one (renamed) file;
- filenames must be globally unique (flat VPATH across all process
  dirs).

## Step 4 — hook into the build

The new files must be listed in `driver/makefile` (`PROC<NAME>` variable
+ the appropriate `SRC_DRIVER_*` aggregate) and the src-level
subtraction files in `NNLOJET.mk` (`SUBTRACTION_<PROC>`/`MATRIX_<PROC>`)
— `autoAddFortran.py` automates part of this but review its output (see
add-process-to-driver). Then build with a full `make -j` in `driver/`
(new files ⇒ never skipdepend).

Validation of the linking beyond compilation: run-layer-check verifies
the integrated-counterterm bookkeeping symbolically; spike tests
(run-spike-test) validate the subtraction terms numerically. Offer both.
Repo is Mercurial; do not commit unless asked.
